# 薬局の日常運用ガイド（操作ガイド）

Status: 2026-09-15 local documentation。対象は dev ブランチの実装済み画面。

この文書は、薬局スタッフと当番責任者が 1 日の業務を回すための操作ガイドです。
画面ごとの手順詳細は `manual-staff.md`、患者への説明は `manual-patient.md` を参照し、
このガイドは「いつ・どの順で・だれに確認しながら回すか」に絞ります。

営業時間、一次返信の期限、主担当・代行担当などの数値は薬局ごとの担当者判断です。
未決のものは本書で推測して埋めず、「担当者判断（未決）」と明記します
（未決項目の台帳は evidence `v0.35.0-beta-staff-readiness.json` の `operationsPreparation`）。

## 1. 1 日の流れ

### 開店時

1. 管理画面にログインし、サイドバー上部のアカウント切替で自分の薬局の
   LINE アカウントが選ばれていることを確認します。
2. 「ダッシュボード」（本日の対応）を開き、各キューの件数と
   「対応が必要な項目」を確認します。「対象画面を開く →」で該当画面へ進みます。
   「対応が必要な項目」は確認用の読み取り専用一覧で、ここから状態変更はできません。
3. 「期限超過」「本日」の項目から先に片付けます（優先順位は §2）。
4. 「個別チャット」で前日・営業時間外に届いた患者メッセージの未対応を確認します。
   届いたメッセージは通常の相談として扱い、患者への 1 対 1 返信は手動対応として
   記録されます（画面側が自動で区別します）。

### 随時（業務中）

- 各キューは「本日の対応」の件数を目安に巡回します。画面の「再読み込み」で
  最新状態を確認してから操作してください。
- 「読み込み中」「未確認」の表示は「0 件」ではありません。表示が戻らないときは
  「再読み込み」を押して件数を確認してください。
- 状態を進める操作（受付・準備完了・受け渡し完了など）は、押すと患者へ LINE
  通知されます。LINE の送信受付は「患者への到達・既読の確認」ではありません。
  業務状態と通知結果は別々に確認してください。

### 閉店時

- 「本日の対応」で「期限超過」「本日」に残っている項目がないか確認します。
  残った項目は翌開店時の先頭に回すか、薬局のルールに従って引き継ぎます
  （引き継ぎ先の担当者は担当者判断・未決）。
- サイドバー下の「ログアウト」で終了します。

## 2. 対応の優先順位

| 優先度 | 対象 | 理由 |
| --- | --- | --- |
| 1 | 「期限超過」の項目 | 応答期限を過ぎています。まず確認します |
| 2 | 「本日」の項目・緊急避妊薬の「未確認・仮受付」 | 当日中の対応が前提です。仮受付は対面確認が必要です |
| 3 | 個別チャットの未対応 | 患者からの待ち状態です |
| 4 | 「今後」「期限なし」の項目 | 開店時と閉店時にまとめて確認します |

服薬後フォローで「優先確認」（escalated）が付いたものは通常の回答より先に
対応し、対応記録を残してから「完了」にします。対応記録のない完了操作は
システムが拒否します。

## 3. キューごとの要点

各画面の詳細な手順は `manual-staff.md` の該当節を参照してください。

- **処方せん受付**: 「薬剤師確認」（発行元分類・交付日・使用期限）と「受付回答」を
  先に保存してから状態を進めます。使用期限が未確認のままでは受付できません。
- **電子処方箋受付**: 患者の「手続きを終えた」は申告です。必ず薬局側で確認し、
  結果を記録します。
- **緊急避妊薬**: 患者の申告は「申告（未確認）」です。対面で各セクションを再確認し、
  A セクションの確認前に「店頭対応完了」へは進めません。販売記録は保存後に
  修正できません。
- **患者アンケート**: 「再提出依頼」で患者に再回答を求められます。服薬後フォローは
  この画面内のパネルから予約・対応します。
- **継続フォロー**: 「次回事前送信のお知らせ」の送信日時・一時停止・取消を管理します。
- **印刷用画面**: 印刷または PDF 保存が終わった後だけ「印刷操作済みとして記録」を
  押します。キャンセルした場合は記録しません。

## 4. 困ったときの対応

| 状況 | 対応 |
| --- | --- |
| 「状態を更新しました。LINE通知は再試行待ちです。」 | 状態は保存済みです。通知は自動で再送されます。患者から連絡があれば口頭で案内してください |
| 「別の更新がありました」（409・競合） | 他のスタッフが先に保存しています。同じ保存を繰り返さず、最新状態を確認してから編集し直してください |
| 「受付回答が変わりました」 | 入力は保持されています。「入力を破棄して再読み込み」で最新の版を確認してから編集し直してください |
| 「セッションの有効期限が切れました」 | もう一度ログインしてください |
| 一覧・詳細が「読み込み中」のまま戻らない | 「再読み込み」またはブラウザの再読み込み。改善しなければシステム担当へ連絡してください |
| 画像が開けない | 「画像を取得できませんでした」の表示後、再度お試しください。繰り返す場合はシステム担当へ |
| 患者と LINE 利用者の紐付けが誤っている | `WRONG_BINDING_RECOVERY.md` の手順に従います。本人確認後に紐付けを停止し、正しい利用者から新規登録してもらいます。停止した紐付けをその場で復活させてはいけません |
| システム障害・通信断で受付が回らない | 電話・店頭での通常対応へ切り替えます。復旧時の切り戻し手順と連絡網は担当者判断（未決・V035-6）です。障害中の操作を推測で記録しないでください |
| 非参加の患者から機能利用の相談 | beta 参加登録がない患者は対象機能を利用できません（画面上は案内が出ます）。同意の撤回などの本人操作は参加状態に関わらず利用できます。通常の相談は個別チャットで受け付けられます |

## 5. エスカレーション先

| 内容 | 連絡先 |
| --- | --- |
| 画面の使い方・表示の確認 | まず本書と `manual-staff.md`。それでも不明なら薬局内の管理者（オーナー/admin） |
| 機能設定・患者向け薬局情報・個人情報の取扱いの変更 | オーナーまたは管理者（一般スタッフは閲覧専用のため） |
| パスワードを忘れた | 全体管理者（platform admin）に仮パスワードの再発行を依頼 |
| 誤紐付け・法令対応（開示・消去請求） | `WRONG_BINDING_RECOVERY.md`・`manual-staff.md` §8 の手順に従い、管理者と確認 |
| 障害・復旧・繰り返すエラー | システム担当（販売元の運用担当） |

## 6. やってはいけないこと

- 患者の氏名・病名・薬名など個人情報を LINE の自動通知文やテンプレートに
  書かない（通知は中立的な定型文のみ）。
- 患者の「手続きを終えた」「仮受付」を正式な受付・販売確定として扱わない。
  必ず薬局側で確認して記録する。
- 管理画面の画面写しを外部に送らない。
- 営業時間・返信期限・担当者など未決の運用値を推測で入力・記録しない。
- 通信エラーのあと、結果が不明なまま同じ保存・記録を繰り返さない
  （最新状態を確認してからやり直す）。
- 薬局コードとパスワードを薬局外で共有しない。
